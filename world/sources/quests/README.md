# Quest data — the province's quest skeleton

The quest index used to be a markdown table
([docs/quests/55-quest-index.md](../../../docs/quests/55-quest-index.md)). The
province needs **450–550 quests at maturity** (Morrowind density,
[research §4](../../../docs/research/morrowind-content-density.md)), written by
region agents working in parallel. One table cannot take eight writers at once
and nothing checked it, so the index is data now and the markdown is generated.

Loader/validator: `tooling/world-generation/worldgen/quests.py`.
Reading views: `docs/quests/index/` (generated by `worldgen.export_quest_index`).

## The files

| File | Holds | Owner |
|---|---|---|
| `lines.json` | every questline: id, code prefix, name, group, faction, tier, home region, mature target band | quest leads |
| `quests-main.json` | the main-quest spine (MQ, tier 0) | quest leads |
| `quests-factions.json` | the twelve faction lines' spine slots | the line's author |
| `quests-standalone.json` | LQ, DQ, ST and the three ex-main rows (MQ11/12/19) | quest leads |
| `quests-proposed.json` | PP rows: proposals from the plotted province, **not authored** | anyone picking one up |
| `local-<region>.json` | that region's minor side quests — **one file per catalogue region** | **the region agent** |

The last row is the whole point: a region agent writes only
`local-<region>.json`, so eight agents can work at once without touching one
another's file, and the index regenerates from all of them.

## Shape

```json
{ "schemaVersion": 1, "packet": "local-dunmer-north", "seed": "quests-local-dunmer-north-v1",
  "budgetExceptions": {},          // optional; see the shape budget below
  "quests": [ { ... } ] }          // sorted by id
```

Quest fields:

| Field | Rule |
|---|---|
| `id` | `quest.<line-slug>.<code-lower>`, globally unique, **never reused** (standard 2) |
| `code` | the authoring handle: two capitals, two digits (`LQ42`) |
| `title` | player-facing working title; the displayed string lives in `packages/text-catalogue` (standard 3) |
| `line` | a `quest.line.*` id from `lines.json` |
| `group` | must equal the line's group: `main` / `faction` / `line` / `local` / `daedric` / `proposed` — this is what the World Studio map filters by |
| `tier` | 0–3, per [40-factions.md](../../../docs/quests/40-factions.md) §30b; a brief may not write anything a lower number owns |
| `status` | `live` (brief exists) / `concept` / `skeleton` / `proposed` |
| `shapes` | **primary first**, up to two secondary, from the 16-shape taxonomy ([index README](../../../docs/quests/index/README.md) §47b) |
| `region` | a catalogue region (`places-<region>.json` name), or null for province-wide |
| `settlement` | a `place.` id of a **live** record classified `settlement`, and also in `anchorPlaces`; null if the quest starts outside a settlement |
| `anchorPlaces` | `place.` ids, sorted and unique, all resolving to **live** catalogue records |
| `premise` | one clause. British spelling, plain sentences, no comma before "and" — the prose linter runs over the generated index |
| `costTier` | `S`/`M`/`L`, or null while unknown |
| `milestone` | 1 or 2 |
| `touches` | shared NPCs, LOCs, STATEs, items and variables the brief reads or writes (§47c step 4) |
| `sources` | the docs the row came from |

## The authoring workflow for a region agent

1. Read [docs/quests/index/README.md](../../../docs/quests/index/README.md)
   (§47a–c: why, the shape taxonomy, the novelty rule) and
   [docs/quests/index/coverage.md](../../../docs/quests/index/coverage.md) —
   the coverage file is the commissioning brief: which shapes are thin, how
   much your region's settlements are short by.
2. Read [docs/quests/index/local-\<region\>.md](../../../docs/quests/index/) and
   the other index views for collisions (§47c step 2).
3. Write rows into `world/sources/quests/local-<region>.json` **and nothing
   else**. Name every place by catalogue id (25 §20f rule 1); a place with no
   live record is a build item, not a note.
4. From `tooling/world-generation`:

   ```bash
   python3 -m worldgen.quests --check              # ids, lines, shapes, anchors, budget
   python3 -m worldgen.quests --sync               # registry + questHooks.tierOwnership
   python3 -m worldgen.export_quest_index          # regenerate docs/quests/index/
   python3 -m worldgen.lint_prose --no-catalogue --md "docs/quests/index/*.md" --report -
   python3 -m pytest -q worldgen/test_quests.py
   ```

`--sync` writes the ids back two ways: it re-derives
`world/sources/registries/quests.json` from the data, and it stamps
`questHooks.tierOwnership` (`"<CODE> · tier-N"`, lowest tier first) onto every
live catalogue record a quest anchors at. Ownership strings it cannot explain
are kept and reported, never dropped.

## The shape budget

55 §47c: **no primary shape may exceed ~20%** of a packet. The budget is judged
against a quest's **line** where it has one, and against its packet otherwise —
a ten-quest faction line inside a 102-row file would never trip a per-file rule.
A recorded departure goes in `budgetExceptions` as
`{"<line or packet key>": {"<SHAPE>": "one-line reason"}}`; the check then prints
a note instead of failing. Three are recorded today and each says how to work it
off.
