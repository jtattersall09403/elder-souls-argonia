# tooling/bootstrap

Scripts that turn a fresh GitHub codespace into a working copy of the build VM. `.devcontainer/devcontainer.json` calls them. The plan behind them is `docs/research/infrastructure/codespaces-migration-plan.md` (Part 3).

The image comes first (`.devcontainer/Dockerfile`). It installs the system packages, rclone, rtk and the asset-pipeline toolchain under `/opt/es-tools`: Wine 11.13 wow64, the Windows build of Blender 4.4.3 with PyNifly V28.1.0 in its `addons_core`, and gltfpack 1.2. Every download is pinned by sha256. There is no X server: Wine and Blender run headless, as on the VM. Then three lifecycle scripts run automatically, in this order, and one script is run by hand:

- `on-create.sh` (onCreateCommand, no secrets, baked by the prebuild) holds only fast installs that cannot wait for input, because the codespace stays in "Provisioning" until it ends. It links `~/tools` to `/opt/es-tools`, where `pipeline/config/toolchain.json` looks, runs the pip installs (world-generation `requirements-test.txt` plus asset-pipeline `requirements.txt`), `npm ci` and `npx --yes playwright install --with-deps chromium`. Each step runs under `timeout` (1, 15, 20 and 15 minutes) with stdin from `/dev/null` and a non-interactive environment (`steps.sh`); its start, end, exit code and seconds go to stdout and `/workspaces/.es-bootstrap/on-create.log`, and a failed or timed-out step stops the script naming the step. Each step writes a marker in `~/.es-bootstrap/`; delete a marker to redo that step.
- `post-create.sh` (postCreateCommand, has secrets) writes the rclone `r2:` remote and `~/.config/nexus/api_key`, both mode 600. If the vault is missing, it clones `/workspaces/elder-scrolls-asset-pipeline` from the `vault-git` bundle and makes a local branch for every bundled branch (`snapshot-vault.sh` bundles `HEAD --branches --tags`, so a bundle re-made here carries them all). It then pulls the `base` tier, the `claude` tier and the `vault` tier (`vault-git`, skipped once the checkout exists, and `vault-worktree`), in that order, with no `--force`. It checks all five secrets below: a missing restore secret stops it with the names, a missing `CLAUDE_CODE_OAUTH_TOKEN` prints a warning (Claude Code will ask you to log in) and the restore goes on.
- `on-start.sh` (postStartCommand, every start) is the one place that derives `ES_TUNNEL_URL` from `ES_STUDIO_PORT`. It replaces its block in `~/.bashrc` on every start (VS Code terminals are interactive bash and read it) and sets `env.ES_TUNNEL_URL` and `env.ES_STUDIO_PORT` in the repo's gitignored `.claude/settings.local.json` (merged, created with mode 600 when absent). The tunnel env lives only there and in `~/.bashrc`, never in `$CLAUDE_CONFIG_DIR/settings.json`, and the `claude-home` snapshot strips both keys from the `settings.json` it tars. It warns if `rtk` is missing.
- `first-run.sh` (by hand, once, from a codespace terminal after `post-create.sh` has finished): **run `bash tooling/bootstrap/first-run.sh` once before kit, settlement or chain work.** It reads the Wine, Blender and prefix paths from `pipeline/config/toolchain.json`, builds the prefix with `wineboot -i` (with `WINEDLLOVERRIDES="mscoree,mshtml="` and no display, so the Wine Mono and Gecko installers never open; the VM prefix has neither) and checks that Blender under Wine loads `io_scene_nifly` (about 1 minute; 15-minute limit; marker `~/.es-bootstrap/wine-prefix.done`). It then runs `vault-pull.sh --tier toolchain --tier cache` (every run; the pull skips parts it holds), prints `df` and `vault-pull.sh --free`, and a ready line. Log: `/workspaces/.es-bootstrap/first-run.log`.

`steps.sh` is the step runner `on-create.sh` and `first-run.sh` share (timeout, log, marker). `lib.sh` holds what the two vault scripts share: paths, manifest reads, and `fingerprint`, the sha256 of the sorted `path<TAB>size<TAB>mtime-seconds` lines of the files in a set.

`snapshot-vault.sh` writes `snapshot-manifest.json` (schemaVersion 1), which lists each part with its `id`, `object`, `bytes`, `sha256`, `root` (relative to the dev root), `tier` (base, claude, vault, chain, toolchain, cache or mod), `archivesPart`, `needsArchives`, `sourceBytes` (information only) and `sourceFingerprint` (the fingerprint of exactly the files the part tars; for `vault-git`, of the vault's refs). A new record is merged over the old one: a field this machine cannot see (an `archivesPart` whose archives were never pulled here) keeps its manifest value. A part is uploaded when its fingerprint differs from the manifest's; `--only <id>` uploads it regardless, `--dry-run` only reports, `--list --files` shows the tar entries. `--force` only re-uploads unchanged parts; it lifts no guard. Two guards, each with its own flag: on a codespace (a `.vault-pull/` marker folder exists) a part already in the manifest is uploaded only if it was pulled there (a part new to the manifest uploads; `--allow-partial` lifts it), and (`--allow-shrink` lifts it) a part whose files add up to less than half the manifest's `sourceBytes` is refused, except `vault-worktree`, `claude-home` and `claude-transcripts`, which shrink honestly (changes committed to the vault, Claude memory or transcripts pruned). Claude transcripts are backed up to the private bucket, never to git. While any `.vault-pull/<id>.done.inprogress` exists (an interrupted pull) it refuses to run and names the parts, and no tar holds a path matching `*.incoming-*` (the old staging name, kept as a guard). The Claude part reads `$CLAUDE_CONFIG_DIR` (default `~/.claude`).

`vault-pull.sh` restores snapshot parts from the R2 bucket. Each part is one uncompressed tar of paths relative to the dev root. It is streamed through `rclone cat | tar -x`, and the sha256 is checked on the same stream. A part whose object is a `.bundle` is saved as a file in `/workspaces/.vault-pull/` and is not extracted. Each pulled part leaves a marker `/workspaces/.vault-pull/<id>.done` of two lines, the part sha256 and the fingerprint of the files its tar held (taken right after extraction), plus a sidecar `<id>.done.files` listing those files. `snapshot-vault.sh` rewrites the marker the same way (`write_marker` in `lib.sh`) after it uploads a part from a codespace, A pull into a root that already exists is staged in `.vault-pull/staging/<id>` (same disk, outside every repo): only once the sha256 matches are the old version's stale files deleted and the new files moved in, so a failed stream leaves the live root and its marker untouched. Eviction runs the same local-change check over the whole root (a file no marker lists, such as a newly downloaded archive, counts as a change): such a root is kept ("kept <root>: local changes") and the next least recently used one goes instead. A pull writes `<marker>.inprogress` before it extracts and removes it after the marker; `.inprogress` records `phase=stream` or `phase=swap`; a staged pull interrupted after its sha256 verified (`swap`) is rolled forward to the new version; otherwise the next pull of an interrupted part removes its staging dir; after a staged pull the live files and old marker stay (still the previous version), after an in-place first pull the files its lists name (no others) are deleted too; then it pulls without `--force`. `.vault-pull/` is created only by a pull that writes. An unknown tier or part id stops with "unknown tier/part: <name>".

To pull a mod folder: `bash tooling/bootstrap/vault-pull.sh mod-sources/<folder>`. Add `--with-archives` for its original archives; a part that has `needsArchives` set gets them anyway. `--tier toolchain` fetches vanilla Skyrim, and only that (`first-run.sh` pulls it). `vault-worktree` holds only the vault's changed and untracked files outside every other part's root, so each file lives in exactly one part. Run `snapshot-vault.sh` (it skips unchanged parts) at the end of any session that changed the vault. Commit tooling/bootstrap/snapshot-manifest.json straight after every snapshot run. Tiers (the repo parts hold only git-ignored files under their own roots, never a tracked file; no `node_modules/` except `repo-water-recovery`, which is one):

| tier | parts | pulled | evicted |
|---|---|---|---|
| base | `skyrim-source-misc`, `vault-extra` (the vault's git-ignored files outside every other part's root, but `build/`: the KotM text corpus under `derived/text/`, `shots/`), `repo-studio-public` (the studio's public data), `repo-wg-products` (world-generation chain receipts, blueprint maps and route/report products), `repo-asset-kits-meta` (the non-GLB sidecars of `tooling/asset-pipeline/output/kits`: what the settlement compile and the footprint check read) | by `post-create.sh` | never |
| claude | `claude-home` (also the repo's `.claude/settings.local.json`, filtered, restored by `post-create.sh` only where the repo has none), `claude-transcripts` (this project's session transcripts, subagent and workflow dirs, tool results: its whole Claude project dir but `memory/`) | by `post-create.sh` | never |
| vault | `vault-git`, `vault-worktree` | once, by `post-create.sh` | never |
| chain | `mod-sources/tamriel-worldspaces-118678` (the base heightfield) | on demand, by whoever runs the terrain chain (`vault-pull.sh --tier chain`) | never |
| toolchain | `vanilla` | by `first-run.sh` (or on demand) | never |
| cache | `vault-output`, `repo-asset-build`, `repo-asset-output` (the rest of `tooling/asset-pipeline/output` minus `sheets/`: the raw kit GLBs used by kit and settlement WORK, i.e. measuring, assembly renders, the interiors index; the studio uses the compressed kits tracked in `apps/world-studio/public/kits`), `repo-wg-mesh-cache`, `repo-water-recovery` | by `first-run.sh`, or on demand (by id or `--tier cache`): kit builds, kit and settlement work (needs the raw kit GLBs in `repo-asset-output`) and the miners | like mod: least recently used, never with local changes, never a git-tracked file |
| mod | every other `mod-sources/<folder>` and its `.archives`, `bmv` | on demand | yes |

World-generation `survey-cache` (rebuilt in about 13 s) and `mesh-cache-work` (scratch) are not carried. `npm run site:compose` rebuilds `site/`. The codespace sets none of `ES_ASSET_PIPELINE_ROOT`, `ELDER_SOULS_ASSET_ROOT` and `ES_VAULT_ROOT`, because each has two meanings in the code (see PROGRESS row); every resolver finds the vault as the repo's sibling. `post-create.sh` stops if any is set, makes the relative links `tooling/asset-pipeline/skyrim-source/{Data,extracted,mod-sources}` into the vault (as on the VM), and checks that `worldgen.vault`, the asset pipeline's `vault_path` and the kit footprints resolve (a link whose tier is not pulled yet is reported as dangling). An upload streams to `snapshot/v1/_incoming/<object>`; unchanged content is dropped there, a change moves the current object to `snapshot/v1/_prev/<object>` and the upload into place (server-side), and the manifest records `prevSha256`; the next run finishes a swap a crash cut short. `vault-pull.sh` falls back to `_prev` when the object no longer matches its manifest. The manifest must be committed and pushed after every snapshot; only one previous version is kept. The vault's deleted-but-uncommitted paths travel in `vault-worktree` as `.vault-worktree-deletions` at the vault root (always present, empty when none); the pull deletes those files from the fresh clone and then removes the list. The vault tier is create-only: `vault-worktree` is extracted once, into the checkout `post-create.sh` cloned (marker `.vault-pull/vault-clone.done`); any later `--tier vault` exits 0 with "vault tier is restored once at create; the vault is edited on one machine at a time (hand over with snapshot-vault.sh)". The vault is edited on one machine at a time and has no GitHub remote: hand over by running `snapshot-vault.sh` on the old machine, committing the manifest, then creating the codespace. `--list` shows every part, `--free` shows free space and the pulled parts, and `--evict <id>` drops a mod part's whole folder. In `--free`, the `vault-clone` row prints `?` for tier and size: its marker (`vault-clone.done`) records the initial git clone of the vault, not a manifest part, so there is no tier or byte count to look up. The parts sharing a root are evicted together, and only if every one of them is tier mod or cache, so `tamriel-worldspaces-118678.archives` is never evicted (it shares its folder with the chain-tier heightfield part). When a pull needs room (its size plus 2 GiB), the least recently used such folders go first. Before extracting, a pull stops if the part's own files changed since its marker, or, with no marker, if any of them already exists here (files added later, such as Claude's session logs, never count). The message is "local changes in <root>: snapshot them first (snapshot-vault.sh --only <id>) or pass --force". With no marker, the part's file list comes from its sidecar object `snapshot/v1/<id>.files` (manifest `filesObject`, a few KB; `snapshot-vault.sh` writes it with every tar, `--backfill-filelists` for existing parts), and a listed file that git tracks and holds unchanged from HEAD (as a fresh clone leaves it) is not a local change; a missing sidecar refuses. `post-create.sh` therefore pulls `vault-worktree` without `--force`. Overrides: `ES_DEVROOT`, `ES_SNAPSHOT_MANIFEST`, `ES_RCLONE_REMOTE`, `ES_VAULT_PULL_RESERVE`, and for tests `ES_PULL_FREE_LIMIT_BYTES` (treats the dev root as a disk of that size).

The Codespaces secrets, scoped to this repo, are `ES_SNAPSHOT_ACCESS_KEY_ID`, `ES_SNAPSHOT_SECRET_ACCESS_KEY`, `ES_SNAPSHOT_ENDPOINT` (with no bucket suffix), `NEXUS_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`. Claude Code reads the last one straight from the environment.

`restore-mods.sh` is the Nexus fallback for when the bucket is lost. Its header documents it.
