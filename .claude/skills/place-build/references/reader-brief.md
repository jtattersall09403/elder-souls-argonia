# Reader brief (the one template for every `image-reader` brief)

Every image-reader brief the place build issues (kit review, workbench render
rounds, walk shots, the feel check, the visual-look judge) is built from this
file and ends with the open question, in the same read, with no extra image
(owner 2026-10-03). Over-specified checklists miss the obviously wrong thing;
the last question asks the reader to step back.

## Fill-in template

> **Context.** Place: <name>, type <type>, region class <class and climate in
> plain words>. Intent mood words: <§ Intent words>. Images: <path: what this
> image or piece is meant to be>, one line each, from the brief that issues it.
>
> **Checklist.** <the rows for this read, below>. Answer each YES / NO /
> UNSURE with the evidence in one line.
>
> **Open question (always last).** Given this context (the place, its type,
> its region, the intent words, what this piece or view is meant to be), does
> what you see feel right for it? If not, what is obviously wrong when you
> step back?

## Which rows

- Render round: the `reader` rows of [reader-checklist.md](reader-checklist.md).
- Kit piece: [kit-review.md](kit-review.md) plus the rows of
  [look-lists.md](../../../../tooling/visual-look/look-lists.md) the tool prints.
- Feel check: the items of [feel-check.md](feel-check.md) § Reader brief.
- Walk shots: the rows of the shot's own reader read (checklist as above).

## Exit rule

A read passes when every checklist row passes and the open answer names
nothing wrong. The open answer is read as a finding like any checklist FAIL:
each wrong thing named becomes a fix row (for a kit piece, a kit-review
finding) before the next round. Standard 14's four-round cap applies.
